# Tower Pulse Implementation Plan

Tower Pulse is the planned public analytics page for Tower Map. This document
turns the product plan in `docs/tower-pulse.md` into an implementation path for
the first web version.

The first implementation should be static, inspectable, and easy to replace
with live aggregate data later.

## Route Shape

Recommended first routes:

```text
/pulse
/en/pulse
/ja/pulse
```

The root route can use the English view by default. Localized routes should
mirror the existing Tower Map route pattern:

```text
app/pulse/page.tsx
app/en/pulse/page.tsx
app/ja/pulse/page.tsx
components/localized-pulse-page.tsx
```

The page should link back to:

- tower homepage
- methodology page
- tenant profiles
- public analytics docs, when useful from a repository context

## Data Source

The first version should import:

```text
reports/analytics-snapshot.json
```

The snapshot is generated by:

```bash
npm run analytics:snapshot
```

The page should treat the snapshot as a public product signal export:

- no client-side secret access
- no Supabase service role usage
- no direct database reads from the browser
- no price or trading data assumptions

## Component Ownership

Recommended component split:

```text
components/localized-pulse-page.tsx
components/pulse-overview.tsx
components/pulse-tenant-table.tsx
components/pulse-floor-table.tsx
components/pulse-category-distribution.tsx
components/pulse-ca-verification.tsx
```

Keep each component presentation-only. Data shaping should happen before props
reach the component whenever possible.

## First Screen

The first viewport should answer:

- What is Tower Pulse?
- How active is the tower?
- Which floor is currently loudest?
- What is the strongest visible public signal?

Suggested first-screen modules:

- title: `Tower Pulse`
- body: `A public signal board for Tower Map activity.`
- total tenants
- total saves
- total notes
- hottest floor

Avoid a marketing hero. This should feel like an operational signal surface.

## Section Order

Recommended order:

1. Tower overview
2. Most saved tenants
3. Most discussed tenants
4. Hottest floors
5. Category distribution
6. CA verification progress
7. Methodology note

This order moves from quick pulse to deeper registry inspection.

## Empty States

The page must look intentional even when the snapshot has little activity.

Use empty states such as:

```text
No public saves have been recorded in this snapshot yet.
```

```text
No Tenant Notes are included in this snapshot yet.
```

```text
Contract verification is still in review.
```

Do not show raw `0` values without context when the section would otherwise
look broken.

## Mobile Layout

Mobile should prioritize scanning:

- overview metrics stack into two-column rows
- tenant tables become compact cards
- floor and category rows use short labels
- long tenant names wrap without changing row height dramatically
- no horizontal scrolling for core content

Avoid dense dashboard cards that require pinching or zooming.

## Accessibility

The page should use semantic sections:

- one `h1`
- clear `h2` labels per analytics section
- tables only when row comparison matters
- descriptive empty states
- text labels for all metric values

Do not communicate heat or category distribution by color alone.

## Future Supabase Aggregate Path

The static snapshot can later be replaced by server-side aggregate queries:

```text
tenant_saves -> save counts by tenant_slug
tenant_notes -> visible note counts by tenant_slug
tenants.json -> floor, category, heat, CA status
```

Recommended future API:

```text
GET /api/pulse
```

The API should return the same shape as `reports/analytics-snapshot.json` so the
page does not need to be rewritten when data moves from generated JSON to live
aggregates.

## Release Checklist

Before shipping the first Tower Pulse page:

- `npm run analytics:snapshot` passes.
- `npm test` passes.
- `npm run build` passes.
- The page works for `/pulse`, `/en/pulse`, and `/ja/pulse`.
- Tenant links resolve to profile pages.
- Empty states render when saves or notes are zero.
- Mobile layout fits without horizontal scroll.
- Copy describes Tower Map signal, not market price movement.
